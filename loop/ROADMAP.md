## Hard rules
1. **Facts must be verified** with WebSearch/WebFetch (official site cutiestreet.asobisystem.com, official X/IG/YouTube, Wikipedia JA, reputable news). Never invent birthdays/heights/video IDs/dates. If unverified → omit or mark "확인 중".
   YouTube video IDs must be verified (e.g. WebFetch `https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=ID&format=json` returns 200).
2. **Images**: do NOT download/commit copyrighted member photos into the repo, and do NOT AI-generate likenesses of the real members. Use official embeds (YouTube iframes / `i.ytimg.com` thumbnails), links to official profile pages, and original illustrated/graphic UI (SVG, gradients, member-color art).
3. **Fan page only — no study/learning content** (user, 2026-11-17: "공부 관련된 건 다 빼자 그저 팬페이지다"). The /japanese/ section, flashcards/SRS/word bookmarks/study dashboard and all '배우기' sections were removed in #69. Do not add language lessons, vocab tables or learning quizzes; fan trivia quizzes (member/song facts) are fine.
4. Each iteration must end with `npm run docs:build` passing AND a Playwright visual check (desktop 1440 + mobile 390) of changed pages via `npm run docs:preview` (port 4173, base `/custo/`). No console errors. Respect `prefers-reduced-motion`.
   - Build + serve with `bash loop/preview.sh` (exits 1 if the build fails; always restarts the preview and waits until the fresh build's assets answer — a leftover server serves stale HTML whose assets 404, which happened in #47 and #142). After ANY later data/code edit, run it again before the browser check and before pushing.
   - Link rot: `python3 loop/linkcheck.py` (external pages + every YouTube id; exit 1 if anything needs a look) — run it about weekly or after bulk data edits.
   - Sweeps (run via Playwright MCP `browser_run_code_unsafe` with `filename`; each expects `{}`; long ones move to the background and notify). Parameters travel in the MCP tab URL — `browser_navigate` to `about:blank#w=…` first (globalThis does NOT persist between runs, #198); check the report keys show the width you asked for.
     - `loop/audit.js` — layout + console (+ `cut`: text hidden past a clipping ancestor, #209), 32 pages; `#w=390,1440` (default) or `#w=320` for reflow. Known-benign spill: .sat .mb .stop .col (.sn-t for long titles).
     - `loop/a11y.js` — names, alt, labels, duplicate ids, focusables in aria-hidden (390+1440, clock 11/26 19:20).
     - `loop/contrast.js` — text on gradients, glyph-pixel contrast; default 1440, `#w=390`, `&set=members` for the eight member pages (run all four combos).
     - `loop/cls.js` — layout shift, 24 pages × 390/1440, SW blocked; re-run after data changes too (#204).
     - `loop/targets.js` — WCAG 2.2 target size at 390.
     - `loop/lang.js` — Japanese text without lang=ja (one known: the birthday-ring SVG, inside role=img).
     - `loop/headings.js` — heading outline (h1 first, no skipped levels).
     - When: after the change for the pages touched; the full set every ~10 iterations or after site-wide CSS/data changes (last full set: #205–#206).
5. Commit on branch **`fanpage-overhaul`**. One focused commit per iteration, conventional message, with the Co-Authored-By trailer, then **`git push origin fanpage-overhaul`** AND deploy: **`git push origin fanpage-overhaul:main`** (fast-forward only; user request 2026-11-17 — main push = GitHub Pages deploy). Only deploy when build + visual check passed. Afterwards check `gh run list --branch main --limit 1`.
6. Iteration scope: pick the top 1–3 RICE items that fit ~20 min. Small and shipped > big and broken.
7. Keep the site Korean-first UI, with Japanese names/terms alongside.
8. **Every iteration: also look for today's off-channel appearances** (YouTube search sorted by upload date for CUTIE STREET / 큐티스트리트 / きゅーすと, official X, news) and add verified ones to `docs/.vitepress/data/highlights.ts` so the home '오늘의 큐스트' stays current.
